# ADR-007: Migrate from nbdev to Pure Python + Quarto

- **Status:** Active
- **Date:** 2026-07-10
- **Author:** session 2026-07-10


- Python files in `healpyxel/` are auto-generated artifacts — direct edits are forbidden by project policy (`.ai/00_CONSTRAINTS.md`). This creates a two-step workflow: edit notebook → export → commit generated Python.
- IDE support is limited: notebooks lack autocomplete, refactoring, and type-checking that pure `.py` files provide.
- Testing is split: handwritten tests in `tests/` plus auto-generated tests in `healpyxel/tests/` from notebook cells. This is confusing for contributors.
- nbdev is a niche tool. New contributors must learn its workflow before being productive.
- The OVERVIEW.md target architecture already specifies a pure Python + Quarto target state — this ADR ratifies that direction.

A percent-format bridge already exists in the repo (`nbs/83_example_accumulation-back.py`), proving that `.py:percent` works as an intermediate representation compatible with Jupyter, VS Code, and Quarto.

## Decision

Migrate from nbdev to pure Python + Quarto:

1. **Source of truth:** `healpyxel/*.py` files become hand-edited (no auto-generation). Notebooks are no longer the source of truth. The existing nbdev-exported `healpyxel/*.py` files are **cleaned up** — strip nbdev scaffolding (`#|` remnants, `nbdev` imports, auto-inlined docstring artifacts), delete `_modidx.py` (auto-generated module index), improve docstrings manually, consolidate imports — not rewritten from scratch.
2. **Percent-format examples:** Convert tutorial notebooks `nbs/80-83_*.ipynb` → `notebooks/*.py:percent` via jupytext. These serve as both tutorials and Quarto doc inputs. Library notebooks (`nbs/00-07_*.ipynb`) are not converted — their code is already decompiled into `healpyxel/*.py` during Phase 1 cleanup, and the notebooks themselves are deleted.
3. **Documentation:** Quarto replaces nbdev for docs. `docs/_quarto.yml` uses the `jupyter` engine for `notebooks/*.py:percent` files. API reference generated by [`quartodoc`](https://github.com/machow/quartodoc).

**Docs content strategy — py:percent over markdown→qmd:** The alternative (convert `nbs/` markdown to `.qmd` files with embedded Python) would create a parallel narrative layer that must be kept in sync with the actual library code. With `.py:percent`, nbdev's existing markdown cells become Quarto markdown cells, and code cells execute as part of the docs build. Narrative and running code share one file — no content drift, automatic figure regeneration.
4. **Tests:** Migrate all tests to `tests/test_*.py` using pytest. The current `healpyxel/tests/` directory contains auto-generated test modules (prefixed with `# AUTOGENERATED! DO NOT EDIT!`, sourced from `nbs/*_test.ipynb` cells). These are extracted into `tests/test_*.py`, stripped of cell markers and autogen headers, and wired to use the existing `tests/conftest.py` fixtures. The `healpyxel/tests/` directory is deleted.
5. **Constraints update:** Remove nbdev from required technologies. Add percent-format as required. Remove "Editing `healpyxel/*.py` directly" from forbidden patterns.
6. **Additional repo cleanup:** Several nbdev-era artifacts exist at the repo root or in unexpected locations and must be removed:
   - `settings.ini` (nbdev config, obsolete)
   - `_scripts_original/` (intermediate artifacts from the original script→notebook conversion workflow)
   - `convert_scripts_to_notebooks.py` (nbdev-specific utility)
   - `accumlutaor_example.py` at repo root (orphaned, needs placement decision: move to `examples/` or delete)
   - `_extensions/` at repo root (contains `data-intuitive`; if a Quarto shortcode, move to `docs/_extensions/`; otherwise delete)
   - `healpyxel/coverage.json`, `healpyxel/htmlcov/` (test artifacts leaking into package dir)
   - `.coverage`, `dist/`, `htmlcov/` at root (pytest/build artifacts)
   - All nbdev-generated `.md` and `.html.md` files in `docs/` (stale build output — Quarto render will regenerate from scratch; only manually-authored static assets like diagrams are preserved)

7. **ADR-003 superseded:** This decision replaces the prior commitment to nbdev literate programming.

## Execution order and dependencies

Phases must run sequentially — not all in parallel:

1. **Phase 3** (cleanup `healpyxel/*.py`) must complete before **Phase 4** (delete artifacts), because you need to know which module files to keep. Do not delete `_modidx.py` before confirming the module files are cleaned up.
2. **Phase 2** (convert notebooks to percent) must complete before **Phase 5** (Quarto config), because `docs/_quarto.yml` needs to reference the `notebooks/*.py:percent` files.
3. **Phase 8** (migrate tests) can run anytime after **Phase 4** deletes `healpyxel/tests/` — the test bodies are independent of the cleanup work.
4. **Branch:** Migration runs on the existing `dev` branch. `master` is clean and contains the latest `nbdev_export` output as a known-good rollback point.
5. **Backout strategy:** If the migration breaks mid-way, `git reset --hard origin/dev` returns to the pre-migration state on `dev`. `master` is untouched and contains the latest working nbdev-exported `healpyxel/*.py` for recovery. No data loss risk — `master` and `dev` are in sync before migration starts.

## Version handling

`__version__` stays in `healpyxel/__init__.py` (single source of truth, maintained by hand). The Quarto docs in `docs/_quarto.yml` reference this version via a variable or literal — verify the version string in the docs config matches `healpyxel/__init__.py` after cleanup.

## Skipped files

- `OVERVIEW.md` — created specifically to guide this transition. Becomes stale after migration; not updated, not deleted (historical artifact).
- `PACKAGE_AUDIT.md`, `QUICKSTART.md` — auxiliary LLM-feeding documents. Not part of the migration scope.

## Alternatives Considered

- **Stay with nbdev**: Rejected. The workflow friction (forbidden direct edits, IDE limitations, contributor onboarding) outweighs benefits. The project is mature enough that notebooks-as-source-of-truth is no longer needed.
- **Hybrid: keep nbdev for some modules**: Rejected. Partial migration creates split workflows and configuration complexity. Either nbdev is the source or it isn't — partial commitment provides the worst of both worlds.
- **Markdown → qmd conversion for docs**: Rejected as sole doc approach. Converting `nbs/` markdown to `.qmd` files with embedded Python would mean two parallel sources of truth — running code and narrative text — that must be kept in sync separately. Chosen instead: `.py:percent` scripts where narrative and code share one file.

## Consequences

### Positive
- Direct editing of `healpyxel/*.py` — no more two-step export workflow
- Full IDE support: autocomplete, refactoring, mypy/ruff linting
- Standard pytest workflow — all tests in one place
- Lower contributor onboarding barrier — nbdev knowledge not required
- Percent scripts work in Jupyter, VS Code, and Quarto — no notebook-specific tooling
- Cleaner git diffs for Python code vs. notebook JSON diffs

### Negative
- Loss of nbdev's literate programming workflow — tests are no longer co-located with code in notebooks
- Migration effort: convert tutorial notebooks to percent format, cleanup existing `healpyxel/*.py` (strip nbdev scaffolding, delete `_modidx.py`, improve docstrings), extract auto-generated tests from `healpyxel/tests/` into `tests/test_*.py`, remove nbdev artifacts scattered at repo root (`settings.ini`, `_scripts_original/`, `convert_scripts_to_notebooks.py`, `.coverage`, `dist/`, test coverage files in package dir)
- Nbdev's `#| export` + showdoc inline API docs are replaced by quartodoc — API reference rendered directly in Quarto
- One-time churn in git history (notebooks move directories, generated files disappear)

### Trade-offs accepted
- Some markdown cells in notebooks that were previously auto-inlined as docstrings will now need manual docstring work on exported functions. This is acceptable because force-fitting docstrings via `#| export` is fragile.
- The percent-format scripts (`notebooks/`) may drift from the library API over time. Mitigated by adding a CI check that percent scripts execute without error.

## Waiver

> Quote: `Editing healpyxel/*.py directly — Reason: Notebooks in nbs/ are the source of truth; Python files are auto-generated`
(From `.ai/00_CONSTRAINTS.md`, "Forbidden Patterns")

**Waived:** After this migration, `healpyxel/*.py` files are the source of truth and may be edited directly.

**Why acceptable:** The constraint exists to prevent divergence between notebooks and auto-generated Python. Once notebooks are demoted to examples, the source-of-truth conflict disappears. Direct edits are the normal and expected workflow.
