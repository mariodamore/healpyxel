## [0.3.0] - 2026-07-14

### Summary
v0.3.0 is a major infrastructure release: the project migrates from nbdev to pure Python + Quarto, introduces body-geometry backends (Ellipsoid, DSK), switches sidecar pairing to a pure spherical path, and adds a utility for HEALPix cell size reference tables.

### Changed

#### Architecture
- **feat**: Migrate from nbdev to pure Python + Quarto (ADR-007)
  - All `healpyxel/*.py` files are now hand-edited source of truth (no auto-generation)
  - Removed nbdev scaffolding: cell markers, AUTOGENERATED headers, `_modidx.py`, `settings.ini`
  - Tutorial notebooks converted to `notebooks/*.py:percent` format
  - Documentation rebuilt with Quarto + Jupyter engine; API reference via quartodoc
  - Test suite consolidated to `tests/test_*.py` (was `healpyxel/tests/`)
  - `pyproject.toml` restructured: dynamic version, griffe dev dependency, removed nbdev/geopandas optional extras
- **feat**: CLI submodule segregation (ADR-009) — each submodule exposes `run(config)` and `parse_arguments(argv)`; `cli.py` is a thin gateway

#### Sidecar
- **feat**: Pure spherical fuzzy-mode pairing (ADR-013)
  - Replaced STRtree + shapely cell geometry + dense sampling with `healpy.query_disc` + spherical point-in-polygon
  - No antimeridian, no shapely cell polygons in the computation hot path
  - Great-circle arc sampling via SLERP; interior/bounding-box corner sampling retained for coverage

### Added

#### Core Module
- **new**: `healpix_cell_sizes(body_radius_km, nside=...)` returns a DataFrame with `nside`, `cells`, `angular_size_deg`, and `cell_size_km` for planetary bodies

#### Geometry Module
- **new**: `geometric` module with pluggable body backends:
  - `Sphere` — point-sphere (Moon, Mercury)
  - `Ellipsoid` — oblate spheroid (Earth, Mars, Venus)
  - `SpiceDSK` — SPICE DSK backend (stub)
  - `BodyGeometry` protocol for custom backends
  - Used at the I/O boundary: input lon/lat → xyz → unit vector HEALPix indexing → back to lon/lat

### Fixed
- **fix**: `pd.read_parquet()` does not accept `nrows`; sidecar now reads schema + first 100 rows with `.head(100)` for column auto-detection
- **fix**: `parse_arguments` was missing arguments in some submodules; corrected argument registration

## [0.2.2] - 2026-02-18 

### Summary
v0.2.2 improves streaming accumulator robustness and sidecar I/O flexibility. Key changes: `StreamingStats.update()` now accepts flexible input types, TDigest serialization guarantees centroid materialization, and a new three-tier lazy parquet reader gracefully handles broken spatial partition metadata. The sidecar module gains a dual-workflow architecture for efficient scalar lon/lat processing.

#### Accumulator Module
- **ENHANCED:** `StreamingStats.update()` now accepts scalars, lists, and numpy arrays
  - Auto-converts to 1D float64 array internally
  - Raises `ValueError` for non-1D inputs with clear shape message
- **NEW:** `_serialize_tdigest_raw()` function for aggressive TDigest serialization
  - Uses native TDigest `.to_dict()` method to force centroid materialization
  - Fallback to empty state on serialization failure
- **REFACTORED:** `CellAccumulator.to_dict()` uses aggressive serialization
  - Guarantees centroids are materialized even if percentiles were never queried
  - Fixes edge case where lazy TDigest state could produce empty serialization
- **ENHANCED:** `accumulate_batch()` improved robustness
  - Source_id uniqueness validation with actionable error
  - Proper `state.copy()` to avoid mutation of existing state
  - Improved fuzzy mode documentation (one row per touched HEALPix cell)
  - Better handling of DataFrame index → source_id conversion
- **REFACTORED:** `save_state()` rewritten for flat metadata schema
  - Uses pyarrow `schema` parameter for proper metadata embedding
  - Flat metadata structure consistent with `HEALPyxelxMetadata.to_dict()`
  - Direct JSON sidecar write (bypasses internal validation)

#### CLI Module
- **ENHANCED:** `sidecar_cli()` now validates input before invoking main
  - Logs mode, lon-convention, and nside parameters
  - Raises `FileNotFoundError` with path for missing input
- **NEW:** `validate_lon_lat_columns()` function for column detection
  - Auto-detects from common names: lon/longitude/spot_lon/x, lat/latitude/spot_lat/y
  - Provides actionable error messages with available columns listed
  - Returns validated (lon_col, lat_col) tuple

#### Sidecar Module
- **REFACTORED:** `process_partition()` dual-workflow architecture
  - Workflow 1: Scalar lon/lat columns (efficient for strict mode, no geometry overhead)
  - Workflow 2: Geometry-based (for fuzzy mode with polygon overlap)
  - Clear error when neither workflow is available
- **NEW:** `_read_input_lazy()` three-tier lazy parquet reader
  - Tier 1: dask_geopandas (preserves spatial metadata)
  - Tier 2: plain dask.dataframe (graceful fallback for broken spatial partitions)
  - Tier 3: IOError with clear diagnostic
  - Documents that spatial partitions provide zero benefit for HEALPix assignment
- **ENHANCED:** `main()` passes `lon_col`/`lat_col` to partition processing
  - Enables scalar workflow when geometry is not required

## [0.2.1] - 2026-02-18 

### Summary
v0.2.1 fixes the GeoParquet CLI output (now correctly writes merged geometry + aggregate data) and adds geometry validation utilities. Includes overwrite control for `save_healpix_to_geoparquet()`, enhanced docstrings across core modules, and expanded test coverage for sidecar type coercion.

#### Geospatial Module
- **FIXED:** `to_geoparquet` CLI writes merged GeoDataFrame
  - Previously called `save_healpix_to_geoparquet()` which produced empty grid
  - Now writes geometry + aggregate data columns correctly
- **NEW:** `is_geometry_valid()` function to validate geometries for spherical projection
  - Checks bounds: latitude ∈ [-90, 90], longitude ∈ [-180, 360]
  - Returns False for empty or invalid geometries
  - Prevents spherical projection failures downstream
- **ENHANCED:** `save_healpix_to_geoparquet()` now supports overwrite control:
  - New `overwrite` parameter (default: False)
  - New `interactive` parameter for confirmation prompts
  - Raises `FileExistsError` if file exists and overwrite disabled
  - Added progress message on successful write
- **REFACTORED:** Geospatial CLI main() simplified
  - Delegated GeoParquet generation to `save_healpix_to_geoparquet()` (DRY principle)
  - Removed redundant dense-mode safety checks (moved to function layer)
  - Consistent overwrite handling across sparse/dense paths

#### Core & Accumulator Modules
- Enhanced docstrings with module-level overview and usage examples
  - Accumulator docstring expanded with 4-feature block and 3 usage scenarios
  - Core docstring formatted for clarity
- Minor nbdev cell reorganization (no functional changes)

#### Test Modules
- **NEW:** `test_validate_nside_type_coercion()` in sidecar tests
  - Validates numeric type handling (int32, int64, native int)
  - Ensures type coercion works correctly in `validate_nside()`
- Test module index updated in `_modidx.py`

#### Module Index & Metadata
- `_modidx.py` synchronized with new exports:
  - Added `healpyxel.geospatial.is_geometry_valid` entry
  - Added `healpyxel.tests.test_sidecar.test_validate_nside_type_coercion` entry
- All symbol mappings auto-generated by nbdev_export

#### Breaking Changes
- None (backward compatible)

#### Migration Notes
- Existing code calling `save_healpix_to_geoparquet()` without `overwrite`/`interactive` will use defaults (safe, non-destructive)
- `is_geometry_valid()` is new; no migration required

### Migration Guide

**For users calling `load_state()` directly:**
```python
# Old (v0.1.x)
state = load_state(path)

# New (v0.2.0)
state, meta = load_state(path)
```

**For aggregation workflows with `min_count=0`:**
- Workflows using `min_count=0` will now log warnings
- Consider changing to `min_count=1` or higher for production use

**For cache directory configuration:**
- Cache directory precedence changed to: `--cache-dir` > `HEALPYXEL_CACHE` > `XDG_CACHE_HOME` > `~/.cache/healpyxel`
- Set `HEALPYXEL_CACHE` environment variable or use `healpyxel_cache config init` to configure
